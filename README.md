# gradfit-lab — analytic mesh gradients, certified against finite differences

**承诺**：6 个网格拟合场景的**解析顶点梯度**与独立中心差分的余弦相似度为 **1.000000000000**（最大相对误差 **2.15e-9**）；
在 5 个数量级尺度上 30 次复算的最差相对误差 **1.594e-9**、能量降幅漂移 **1.136e-16**；同一场景的梯度采集只要
**0.105 ms**，逐顶点有限差分基线要 **62.085 ms**（**591×** 墙钟，**972×** field 评估次数）。梯度下降 60 步把平均 |f| 从
**0.6328 降到 0.0137**、能量降 **99.09%–99.97%**（6/6；基线固定步长 98.82%–99.88%，6/6 从未更好）。
证书本身经**变异自测**：8 个变异梯度（含只改 1 个顶点）**8/8 全部被抓**，并公开测不到的那一档。

Upstream: none

本项目为原创工具（非 fork、无上游仓库）。

## 这是什么

把「网格拟合到隐式目标曲面」做成一个**可微**工具：能量 `E(v) = mean_j f(p_j)²`（`p_j` 是三角面上的重心采样点，
`f` 是零集为目标曲面的标量场），对顶点位置给出**解析梯度**，再用 Armijo 回溯线搜索下降。
难点不在渲染，而在**梯度是否真的对**——所以仓库的一半体积是证据：一个只读 `field.f`、从不读 `field.grad`
的有限差分 oracle，逐顶点逐分量核对解析梯度。

浏览器端只用同一个 `src/core.mjs` 渲染与交互：拖动迭代滑杆，屏幕上的能量、平均 |f| 与
`data/reference.json` 里 node 烘焙的**同一个数逐位比对**（`===`，不是近似）。

## 怎么跑（一条命令）

```bash
node tools/gen-sample.mjs && node bench/verify.mjs && node bench/bench.mjs
```

`node bench/verify.mjs` 打印每个场景的实测余弦/相对误差，全过退出码 0（本机实测 **28 passed / 0 failed**，exit 0，11.8 s）。
浏览器：`python3 -m http.server 4173` 后打开 `http://localhost:4173/`（three.js 用 importmap 固定版本 `0.170.0`）。

基线与数字**同仓库可跑**：`baseline/naive.mjs` 导出 `naiveGradient`（逐顶点中心差分）与 `naiveFit`
（固定步长、无 line search）；`bench/verify.mjs` 第 4/4b 节就是拿它跑的对照。

**相对标准差披露**：6 场景聚合 workload 的 RSD 为 **1.89%**，单场景 0.105 ms 量级的 RSD 为 **6.1%**
（两次运行分别 9.08% / 1.89%，说明 0.1 ms 档位受计时噪声与 JIT 影响）。因此加速比同时给出**与计时无关**的
field 评估次数比 **972×**（= 6V，V=162，由计数器实测，不是推算）。
**重跑方差随机器负载变化**：同一脚本在干净克隆里实测 6 场景聚合 RSD 可达 **21.4%**、单场景中位 0.196 ms
（本机高负载时比上表慢约 2×）。所以**结论以与计时无关的 972× field 评估次数比为准**，墙钟 591× 只是本次实测值；
`bench/result.json` 里保留了产生它的那一次运行的完整 min/median/p95/stddev。

## 本轮创新

**B 档**：首次把「解析梯度 vs 中心差分」的**可复算证书**做成可交互的网格拟合工具——滑动迭代，
浏览器用同一个 core 实时算出能量，并与 node 烘焙值**逐位相等**（`===`）。
与近期同队仓库的差异：`convexity-cert-lab` / `toi-cert-lab` / `labelcast-lab` / `shadowtime-cert-lab`
的证据维度是**几何谓词**（凸、相交、重叠、遮挡），本项目的证据维度是**微积分正确性**（梯度），
oracle 只读 `f` 不读 `grad`，因此"两边都用同一个 EPS"式的共谋在这里结构上不可能发生。
台账中没有任何「可微几何 / 解析梯度证书」条目。

**诚实边界**：这里没有新数学——`∇E = (2/N)Σ f(p)∇f(p)w` 是标准平方和梯度，gradient check 也是教科书套路
（libigl / PyTorch autograd 都能做 SDF 拟合）。新的只是**把它做成可现场复算、可变异自测、双端逐位一致的证书**，
以及如实给出「这个检查测不到什么」。

`src/core.mjs` 是纯 ES module：不 import three、不碰 `window`/`document`/`navigator`，模块顶层无副作用。

## 已知限制（含有效尺度范围）

- **无绝对阈值**：所有容差都是相对的。梯度证书用 `h = 1e-6 × bbox 对角线`（`hRel` 写在 `bench/result.json` 里）、
  `cosine ≥ 0.999999`、`relErr ≤ 1e-5`（主扫描）/ `1e-4`（尺度扫描）、能量降 ≥ 50%。**没有**面积/长度/角度绝对常量。
- **有效尺度**：1e-6 … 1e6 实测通过（最差相对误差 1.594e-9，漂移 1.136e-16）。该范围外未验证。
- **证书的分辨力上限（已实测披露）**：单个分量 1e-13 相对扰动只产生 1.07e-9 的 relErr，低于 1e-5 门槛，
  **证书看不见**。敏感度下限由 `relErr ≤ 1e-5` 决定，不是「能查一切」。
- **NaN 不会静默通过**：`order=0` 会让重心权重变成 `NaN`（除以 0），本轮真的踩到过——当时 30 行尺度扫描
  全部是 NaN，却因 `NaN < x` 恒为 false 而"通过"。现在 `makeSamples` 强制 order ≥ 1，且 `compareVectors`
  遇到非有限分量直接返回 `cosine=-1 / relErr=Infinity`。这条写在这里，是因为它差点变成一次假证书。
- **oracle 与主实现不共用魔法常量**：FD oracle 只调用 `field.f`，从不调用 `field.grad`；解析路径只调用 `field.grad`。
- **拓扑固定**：只做顶点位移，亏格不匹配的目标不可达。6 个场景全部使用拓扑兼容的目标（球→椭球/超二次/胶囊，
  环→环/双瓣环，管→锥）。torus→torus 的降幅只有 99.09%，是六者最低，如实保留。
- **`f` 不是精确 SDF**：只保证零集是目标曲面，能量单位是 `f²`，不是欧氏距离。
- **优化器**：一阶方法 + 回溯线搜索，60 步；单调下降但不保证全局最优。
- **语料是脚本生成的**（`tools/gen-sample.mjs`，无随机数，两次运行字节一致），不是真实 glTF 资产。
- **浏览器层**只做了静态起页（HTTP 200 + importmap 存在）与 core 共享；未跑无头浏览器（本轮规则禁止）。
